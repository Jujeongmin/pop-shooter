# POP Shooter 기획서 (1차 출시)

작성 2026-11-11. 표시 규칙: **[사용자]** = 사용자가 정한 것, **[판단]** = 기획 중 내가 정한 것(사용자 확인 전), 표시 없음 = 둘이 같이 확인한 흐름.

## 1. 한 줄 소개와 이유

팝배틀의 장난감 캐릭터가 사격장에서 훈련해 강해지고, 점점 큰 장난감 보스를 자동 전투로 쓰러뜨리며 월드를 넘어가는 **방치형 성장 + 환생** 게임. 로블록스 시뮬레이터 장르와 Poki *1 MMA Fighter* 방식 참고 **[사용자]**.

- 왜: Verse8 → CrazyGames → YouTube Playables로 낼 수 있는 시장성 있는 장르라고 판단 **[사용자]**. 팝배틀 에셋(캐릭터·무기·맵 키트)과 서버 코드를 재사용해 제작비를 줄인다.
- 플레이어가 느껴야 할 것: "강해져서 다음 스테이지를 깨고 싶다", "켜두기만 해도 훈련이 쌓인다" **[사용자]**.
- 성공 = 서비스 수준 첫 출시(월드 4 × 스테이지 10, 최소 10시간 분량) **[사용자]** + 광고·결제 수익 발생.

## 2. 목표 · 비목표 · 반목표

**목표**
- 마우스만 / 터치만으로 전부 플레이 가능. PC는 키보드(WASD) 이동도 지원 **[사용자]**.
- 자동 전투: 결과는 능력치로 정해짐, 직접 조준·회피 없음 **[사용자]**.
- 방치 훈련 + 오프라인 보상.
- 환생 시스템(영구 배율).
- 총 구매, 공격력·공격 속도 업그레이드 **[사용자]**.
- 리워드 광고 + VX 결제로 스탯에 도움 되는 상품 판매 **[사용자]**.
- 월드마다 "다른 월드에 왔구나!" 싶은 전용 에셋 **[사용자]**.
- Verse8 첫 출시, 같은 광장의 다른 사람이 보임 **[판단: 사용자가 맡김]**.

**비목표(1차 제외)** **[판단]**
- PvP, 함께 싸우는 협동 전투, 거래, 길드.
- 펫·장비 뽑기(가챠). 업데이트 후보로만 남김.
- 강제 전면 광고.
- 직접 조준 TPS 전투.

**반목표(동작해도 실패인 것)**
- 숫자만 오르는 엑셀 화면 — 강해진 게 화면에서 보여야 함(총 모델·발사 연출·보스 크기).
- 월드가 색만 바뀐 같은 맵 **[사용자]**.
- 광고를 보지 않으면 진행이 막히는 구조.
- 사실적인 군사 분위기(팝배틀 아트 방향 유지: 둥근 플라스틱 장난감, 파스텔 블루·옐로·오렌지·핑크).
- 기기 시계 조작으로 오프라인 보상을 부풀릴 수 있는 구조.

## 3. 제약

- 기술: Vite + TypeScript strict + Three.js(팝배틀과 같은 버전대: three 0.186, vite 8, TS 7). Rapier 물리 **제외** **[판단]** — 평평한 광장 + 원/상자 충돌로 충분.
- 서버: Verse8 Agent8 SDK(`@agent8/gameserver` 2.0.1), 결제 `@verse8/platform`(VXShop), 광고 `@verse8/ads`. 배포 = GitLab develop 푸시(verse8-upload 스킬 점검표 따름).
- Verse8 iframe: safe area 처리(`env(safe-area-inset-*)`·`viewport-fit`) 넣지 않음.
- 가로 화면 기준, PC·모바일 모두.
- 3D 에셋은 사용자가 제작(Codex 2D 레퍼런스 → Verse8 2D to 3D MCP → GLB). 개발 중엔 임시 도형 사용 가능, 완성도 낮은 3D 모델을 임의로 만들지 않음.
- 메모리 체크리스트(`~/.claude/web-game-memory-checklist.md`) 준수: SkinnedMesh clone은 `skeleton.dispose()`, 이펙트 material 공유, 배경음 길면 스트리밍 등.
- 나중 이식: CrazyGames(광고 SDK, 결제는 별도 연동), YouTube Playables(게임 안 결제·외부 서버 연결 제한 가능성 — **출시 전 확인 필요**). 그래서 광고·결제·저장·멀티를 **플랫폼 어댑터** 뒤에 둔다.

## 4. 핵심 루프

```
광장 이동 → 사격장 훈련(자동 + 탭) → 코인 → 업그레이드·총 구매
   → 스테이지 문 → 보스 자동 전투 → 승리: 코인 + 다음 스테이지
                                  → 패배: "DPS N 더 필요" 안내 → 훈련으로
   → 막히면 환생 → 영구 배율 → 더 빠르게 다시 성장
접속 안 함 → 오프라인 보상(서버 시각 기준)
```

### 4.1 광장(월드 허브)
- 월드마다 광장 하나. 안에 **사격장, 업그레이드 기계, 총 상점, 스테이지 문 10개(길 따라 배치), 환생 제단, 순위판**.
- 이동: PC WASD + 마우스 클릭 지점 이동, 터치는 탭한 곳으로 이동 + 왼쪽 떠다니는 조이스틱(팝배틀 `TouchInput` 재사용) **[판단]**. 시설 근처에 가면 큰 버튼 뜸(탭 하나로 사용).
- 카메라: 3인칭 위에서 비스듬히 따라감, 드래그로 회전 **[판단]**.
- 처음 3분 튜토리얼: 화살표로 사격장 → 업그레이드 → 1-1 문 순서 안내 **[판단]**.

### 4.2 훈련(사격장)
- 사격장 칸에 서면 캐릭터가 과녁을 자동 사격. 초당 발사 수 = 공격 속도.
- 발사 1회당 코인 = 공격력 × 사격장 등급 배율 × 부스트.
- 탭/클릭 1회 = 추가 발사 1회(초당 최대 8회 인정) **[판단]**. 화면 어디든 탭 가능, 탭할 때 과녁에 큰 팡! 효과.
- 사격장 등급: 월드마다 더 좋은 사격장(배율 ×1, ×4, ×16, ×64 **초기값**). 해당 월드가 열려야 씀.
- 게임 켜둔 채 아무것도 안 해도 훈련 계속(방치). 탭이 숨겨지면 RAF가 멈추므로 다시 보일 때 경과 시간만큼 한 번에 정산(최대 오프라인 한도까지, 온라인 정산은 100% 속도) **[판단]**.

### 4.3 성장 요소
| 요소 | 효과 | 비용 |
|---|---|---|
| 공격력 레벨 | 발당 피해·훈련 코인 | 코인, 지수 증가 |
| 공격 속도 레벨 | 초당 발사 수(상한 있음) | 코인, 지수 증가 |
| 총 | 피해 배율 + 모델 교체(강해진 게 보임) | 코인(한정 총은 팝젬/VX) |
| 환생 배율 | 모든 피해·코인에 곱 | 환생 |
| 공격력 패스 | ×2~×64 | VX |
| 부스트 | 일정 시간 코인/훈련 2배 | 광고·팝젬 |

- **DPS = 공격력 × 공격 속도 × 총 배율 × 환생 배율 × 패스 배율**. 훈련 코인/초 = DPS × 사격장 배율 × 부스트(부스트는 코인에만, 피해에는 안 붙음).
- 총: 월드당 4자루, 총 16자루 **[판단]**. 각 총은 앞 총 피해 ×2.5 **초기값**. 1차는 팝배틀 무기 GLB 5종(라이플·샷건·스나이퍼·권총·근접 → 근접은 제외, 4종)을 월드별 재질·색 변형으로 16자루 구성, 이후 월드 전용 총 GLB로 교체 가능 **[판단]**.
- 공격 속도 상한 초당 12발 **초기값** — 이후엔 공격력으로만 성장(무한 성장 축은 공격력).
- 업그레이드 공식 **초기값**(시뮬레이터로 조정):
  - 공격력 레벨 L: 공격력 = (1 + L) × 2^floor(L / 25), 다음 레벨 비용 = 10 × 1.12^L.
  - 공격 속도 레벨 M: 초당 발사 = min(12, 1 + 0.25 × M), 다음 레벨 비용 = 25 × 1.25^M.
  - 총 가격: 0번 총(시작 권총) 무료, 나머지 = 기준 스테이지 체력 × 8 (월드 1: 2·4·6번, 월드 2~4: 앞 대장·2·4·6번). 그 총의 월드가 열려야 살 수 있음 **[구현 중 판단]**.
  - 스테이지 첫 클리어 코인 = 그 보스 HP × 2, 재도전 = HP × 0.3.
- 탭 보너스는 DPS 계산에 포함(초당 최대 8회 × 공격력 × 배율). 서버 검사도 이 최대치를 포함해 계산.

### 4.4 스테이지 전투(자동)
- 스테이지 문 앞에서 탭 → 같은 월드 안 전투 무대(광장과 분리된 작은 아레나)로 이동.
- 캐릭터가 보스를 자동 사격, 보스 체력바·남은 시간·내 DPS 표시. 탭하면 추가 발사(훈련과 같은 규칙).
- 제한 시간: 일반 20초, 월드 대장(10번) 30초 **초기값**. 시간 안에 체력 0 = 승리.
- 결과는 DPS로 정해지지만 연출은 크게: 명중 숫자, 보스 흔들림, 체력 구간마다 보스 표정·색 변화, 쓰러질 때 장난감처럼 튀며 분해.
- 패배: "이 보스는 DPS ○○ 필요(지금 △△)" + 가장 효율 좋은 다음 업그레이드 안내 버튼.
- 승리: 첫 클리어 코인 보상(크게) + 재도전 보상(작게, 반복 파밍 가능) + 다음 문 열림. 월드 대장 첫 클리어 = 다음 월드 광장 열림 + 팝젬.
- 보스 체력: 공식 대신 **시뮬레이터가 목표 시간에 맞춰 만든 표**(`src/sim/stageTable.ts`, `npm run sim -- --fit`). 지수 공식 하나로는 앞뒤 시간을 맞출 수 없었음(초기 공식 = 40스테이지 6분) **[구현 중 판단]**.
- 보스는 반격하지 않음(시간 제한만) **[판단]** — 체력 스탯을 하나 더 두지 않아 규칙이 단순.

### 4.5 환생
- 해금: 1-10(월드 1 대장) 첫 클리어 후 **[판단]**.
- 초기화: 코인, 공격력·공격 속도 레벨, 코인으로 산 총.
- 유지: 스테이지 클리어 기록·열린 월드, 팝젬, 캐릭터, VX 상품, 한정 총, 환생 토큰.
- 보상: 환생 토큰 = 이번 회차 최고 스테이지 기준(예: `max(1, floor((최고 스테이지 − 5) / 2))` **초기값**). 환생 배율 = **1 + 0.5 × 누적 토큰** **초기값**.
- 환생 직후 스테이지는 클리어 기록 그대로라 최고 스테이지 다음부터 도전. 약해진 상태로 재성장 → 배율 덕에 이전보다 빨리 회복하는 맛.
- 환생 확인 창: "공격력 ×N → ×M" 미리보기.

### 4.6 오프라인 보상
- 접속 안 한 시간 동안 훈련 50% 속도로 적립, 최대 2시간 **초기값**(VX로 8시간).
- 계산은 **서버**: 마지막 저장 서버 시각 → 지금 서버 시각. 클라이언트 시계 안 씀 **[판단]**.
- 복귀 창: "자리 비운 동안 ○○ 코인" + [받기] [광고 보고 2배].

### 4.7 시간 배분 목표(최소 10시간)
| 구간 | 누적 플레이 시간 목표 | 환생 |
|---|---|---|
| 1-1 클리어 | 1~2분 | — |
| 월드 1 끝(1-10) | 약 1시간 | 없이 깸 |
| 월드 2 끝 | 약 3시간 | 1~3회 |
| 월드 3 끝 | 약 6시간 | 여러 번 |
| 월드 4 끝(4-10) | 10시간 이상 | 여러 번 — 장기 목표 |

- 무과금·광고 시청 안 함 기준. 광고 적당히 보면 약 20% 단축, 상위 패스 사면 크게 단축 **[판단]**.
- 위 공식의 **초기값은 맞춰 보기 위한 출발점**이다. 구현 때 `tools/sim/` 진행 시뮬레이터(최적 구매 순서 + 환생 시점 탐색 봇)를 먼저 만들고, 이 표에 맞도록 상수를 조정한다(팝배틀 `progression.ts`처럼 목표 시간 → 상수).
- 조정 결과(탭 3/초): 1-1 1분, 1-10 59분, 2-10 2시간 57분, 3-10 5시간 14분, 4-10 10시간 49분(환생 15회). 방치만 하면 4-10 17시간. 상세 `tools/sim/README.md`.
- 숫자 표기: 1.2K → 3.4M → 5.6B → 7.8T → 이후 aa, ab… (`format.ts`) **[판단]**.

## 5. 월드 4개 **[판단: 테마], [사용자: 월드마다 다른 에셋]**

월드마다 바닥·블록·랜드마크·소품·보스·하늘색·배경음이 전부 다르다. 색만 바꾼 재사용 금지.

| 월드 | 테마 | 분위기 | 랜드마크 예 |
|---|---|---|---|
| 1 | 장난감 마을 | 팝배틀과 같은 밝은 파스텔 마을, 블록 집 | 시계탑, 분수 |
| 2 | 블록 공사장 | 노랑·주황 장난감 공사장 | 크레인, 레미콘, 비계 |
| 3 | 사탕 공장 | 분홍·민트, 달콤한 냄새가 날 것 같은 | 컨베이어, 사탕 굴뚝, 롤리팝 나무 |
| 4 | 장난감 우주기지 | 남색 하늘 + 별, 파스텔 금속 | 로켓 발사대, 위성 접시, 달 바위 |

- 월드 1은 팝배틀 맵 키트(Kenney brick·prototype, `src/world/maps/kit.ts` 방식)로 먼저 만들 수 있다. 월드 2~4는 새 에셋 필요.
- 월드별 보스: 일반 스테이지 1~9는 **보스 모델 3종 × 색·크기 변형**, 10번은 전용 대장 모델 1종 → 월드당 GLB 4개, 총 16개 **[판단]**.
- 보스는 **뼈대 없는 태엽 장난감**으로 제작, 코드로 통통 튀기·찌그러짐·흔들림 애니메이션 **[판단]** — 리깅 비용 없음, 장난감 느낌에 맞음.
- 에셋이 오기 전 대체: 크게 키운 팝배틀 캐릭터 + 색 변경, 임시 도형 소품.

## 6. 캐릭터

- 팝배틀 6종(BUBU·MOCHI·ROKO·POPI·SHONI·BAM, GLB 그대로) 재사용. 클립: Idle·Walk·Jog·Jump 3종·Death. 사격 자세는 팝배틀처럼 본 회전으로 만든다.
- 1차: 성능 차이 없음(외형만) **[판단]**. BUBU로 시작, 월드 대장 처치마다 1종 해금(월드 1~3 → 3종), 나머지 2종(SHONI·BAM)은 VX 판매 **[판단]**.
- 무기 장착값은 팝배틀 `config/weapons.ts` WeaponMount 재사용. 새 GLB 검사는 `tools/inspect-glb.mjs --bones` + 실제 장면 확인.

## 7. 멀티플레이 (Verse8) **[판단: 사용자가 맡김]**

- **같은 광장에서 서로 보이기만 함.** 전투·훈련은 혼자, 서로 부딪히지 않음.
- 이유: 남의 높은 레벨·좋은 총·환생 횟수를 보면 성장·결제 동기가 생긴다(시뮬레이터 장르의 핵심). 팝배틀 로비 코드가 이미 있다.
- 룸: 월드별 로비 룸(정원 8, 팝배틀 `lb-N` + 장부 hub_book 방식), 내 현재 월드의 방에 들어감.
- 보이는 것: 캐릭터, 든 총, 머리 위 이름표(닉네임 · 환생 횟수 · 공격력 표기), 훈련 중 발사 연출. 채팅(팝배틀 `ChatService`·필터) 포함.
- 남이 전투 중이면 광장의 그 스테이지 문 앞에 서 있고 이름표에 "전투 중" 표시 **[판단]**.
- 순위판(광장 안 큰 판): 환생 횟수 → 최고 스테이지 → 총 공격력, 상위 10 + 내 순위 **[판단]**. 클라이언트 계산 기반이라 "기록판"으로 표기(공식 랭킹 아님).
- 멀티 층은 꺼도 게임 전체가 돌아가야 한다(이식 대비).
- 재사용: `net/NetClient.ts`·`LobbyHub.ts`·`LobbyPeers.ts`·`nickname.ts`·`shared/nickFilter.ts`·채팅. 복사해서 가져옴(공유 패키지 아님) **[판단]**.

## 8. 저장과 부정 방지

- 원본 = Verse8 서버 계정별 글로벌 사용자 상태. 사본 = localStorage(서버 실패 때 이어하기, 다음 접속 때 합침).
- 저장 주기: 30초마다 + 스테이지 클리어·구매·환생 직후 **[판단]**.
- 서버 검사: 지난 저장 이후 늘어난 코인 ≤ (저장된 스탯으로 낼 수 있는 최대 수입) × 경과 서버 시간 × 1.5 + 스테이지 보상. 넘으면 상한으로 자름. 스테이지는 저장된 DPS로 그 HP를 제한 시간 안에 깰 수 있을 때만 인정 **[판단]**.
- 서버만 하는 것: 오프라인 보상 계산, VX 지급(purchaseId로 중복 방지 — 팝배틀 `$onItemPurchased` 방식), 광고 보상 횟수 제한, 팝젬 증감.
- 닉네임 정책·필터는 팝배틀 규칙 그대로.

## 11. 사운드

- 발사음·처치음은 팝배틀 녹음 파일 재사용(Mixkit·Pixabay, 라이선스 동일).

## 12. 기술 구조 **[판단]**

```
src/
  core/        루프, 입력(GameInput·TouchInput 재사용), 카메라
  sim/         순수 규칙: 스탯·비용·DPS·보스 HP·환생·오프라인 (DOM·three 없음, 서버와 공용)
  world/       광장, 시설, 월드별 장면, 전투 아레나
  battle/      자동 전투 진행·연출
  player/      캐릭터 로드·외형(CharacterAppearance 재사용)·총 장착
  platform/    어댑터: ads / purchase / save / social(멀티)
               verse8/ 구현 먼저, crazygames/·playables/ 나중
  net/         NetClient·LobbyHub·LobbyPeers (verse8 social 구현이 씀)
  ui/          HUD·창
  audio/       AudioManager 재사용
server/src/    저장 검사, 오프라인 보상, VX 지급, 광고 보상, 순위판
tools/sim/     진행 시뮬레이터(상수 조정)
```

- 규칙(`sim/`)은 순수 함수 + `node --test`로 검사. 서버 검사와 클라이언트가 같은 코드 사용.
- 렌더 동기화는 RAF 안에서, UI 숫자는 바뀔 때만 갱신(60fps setState 금지 — 메모리 체크리스트).
- 큰 숫자는 `number`(double) — 1e300 이내로 설계.

## 14. 구현 순서 제안 **[판단]**

1. `sim/` 규칙 + `tools/sim/` 시뮬레이터 → 10시간 표 맞추기(숫자 먼저).
2. 월드 1 광장(팝배틀 키트) + 이동 + 사격장 훈련 + 업그레이드 + 스테이지 1-1~1-10 전투(임시 보스).
3. 환생·오프라인·저장(서버) → 월드 1이 처음부터 끝까지 도는 판.
4. 광고·VX 상품·상점.
5. 멀티 광장(보이기·이름표·채팅·순위판).
6. 월드 2~4 (사용자 에셋 들어오는 대로), 사운드, 튜토리얼, 출석.
7. 이식 준비(CrazyGames 어댑터) — 1차 출시 뒤.
