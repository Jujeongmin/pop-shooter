# POP Shooter 계획 3: 결제·광고

설계 문서 9장(수익)과 7장(서버 검사). 사용자 결정(2026-11-11): VX 상품 = 공격력 패스 ×2~×64, 팝젬 묶음 소·중·대, 캐릭터 SHONI·BAM (환생 건너뛰기는 이번에 안 함). 광고 = 문서대로(코인 2배 15분·누적 최대 2시간, 오프라인 보상 2배, 하루 선물 상자 5회). 강제 광고 없음.

## Global Constraints

- verse8-upload 스킬 4~7장: 결제 지급은 서버 `$onItemPurchased`(계정 락 + purchaseId 기록, 목록은 `.slice(-50)`), 광고 보상은 `status === 'rewarded'`만, 큰 보상은 서버가 requestId로 확인, 가격은 VXShop 조회값(못 받으면 구매 버튼 끔), 광고는 사용자 동작 안에서만.
- **프리미엄 값은 서버 소유**: 팝젬·공격력 패스·부스트 끝 시각·유료 캐릭터는 클라이언트 저장값을 믿지 않고 서버 값으로 덮어씀. 클라이언트는 저장 응답으로 서버 값을 받아 맞춤.
- **코인·진행 검사**: 저장 사이에 늘어난 "가치"(코인 + 산 레벨·총 가격) ≤ 그 시간에 벌 수 있는 최대치 × 1.5 + 스테이지 보상 + 오프라인 보상 한도. 넘으면 코인을 상한으로 자르고, 레벨·총·스테이지가 불가능하면 저장 거절(이전 서버 값 유지). 스테이지는 그 DPS로 깰 수 있을 때만.
- 모든 새 문구 5개 언어. 메모리 체크리스트.
- 작업은 메인 세션에서 직접 (백그라운드 에이전트 없음, 사용자).

## Tasks

1. **서버 경제 검사 + 프리미엄 서버 소유**: 순수 함수 `src/sim/econ.ts`(가치·허용치·검사) + 노드 테스트, `saveWrite`에 적용, 응답에 서버 프리미엄 값, 클라이언트가 받아 맞춤. 서버 하네스 테스트.
2. **리워드 광고**: `@verse8/ads` 래퍼, 서버 `adClaim(kind, requestId)`(종류별 하루 횟수, 중복 requestId 거절), 화면: 부스트 버튼(HUD), 오프라인 창 [광고 보고 2배], 선물 상자.
3. **VX 상점**: `@verse8/platform` 래퍼, 서버 `$onItemPurchased`·`shopOwned`, 상점 창(패스 순서 구매, 팝젬 묶음, 캐릭터), 팝젬 쓰는 곳(부스트 30분). 상품 ID 목록을 사용자에게 전달(대시보드 등록).
4. **확인·배포**: 하네스·노드 테스트, 실서버에서 광고(지원 안 되는 환경이면 버튼 숨김)·상점 조회, 푸시 + 에디터 재배포 요청.
